# route-dance 仕様書

> ステータス: 技術選定レビュー済み（v1）
> 最終更新: 2026-10-17

## 1. 概要

歩行者向けのiOS ARアプリ。カメラ映像から周囲の歩行者の行動を予測し、ユーザーが他の歩行者とぶつからずに歩ける確率の高い経路を算出して、映像上に重ねて表示する。

- 処理はすべてデバイス上で完結する（ネットワーク通信なし）。
- UIのイメージは自動運転車の実験映像のように、リアルタイム映像の上にユーザーが歩くべき一本の道筋を重ねるもの。
- 対応OS: **iOS 27 / macOS 27**（Macは同じアルゴリズム・UIでの動画テスト用）。

### 用語

| 用語 | 意味 |
| --- | --- |
| ユーザー | アプリを使う歩行者本人（カメラを持っている人） |
| 他歩行者 | ユーザー以外の歩行者。軌道予測の対象 |
| 推奨経路 | ユーザーがたどるべき経路 |
| 予測経路 | 各他歩行者が今後とりそうな経路 |
| 予測ホライズン N | 他歩行者の経路を何秒先まで予測・表示するか |
| ゴール | 推奨経路が向かう目標地点 |

## 2. 機能要件

### 2.1 推奨経路の表示（通常モード）

- 推奨経路を一本の線として映像上（地面上）に描画する。
- 推奨経路は**ユーザーの現在の歩行速度でたどれるもの**とする。
- 表示する長さは**現在の歩行速度で約5秒先まで**（`planHorizon = 5s`。長すぎれば調整する）。
  - 停止中も経路が見えるよう、計画に使う速度には下限を設ける（`minPlanningSpeed`）。
- どうしても減速が必要な区間は色で示す。
  - デフォルト（現在速度で通行可能）: 緑
  - 減速が必要: 黄 → 赤（必要な減速量が大きいほど赤）のグラデーション
- 推奨進行方向を示す**コンパス型矢印**を表示する。360°回転し、推奨経路の進むべき向きを指す。

### 2.2 ゴール（行きたい方向）

- v1: **スマホが向いている方向の、地面上で見える一番奥**をゴールとする。
  - カメラの向きを地面に投影した方向に沿って、深度マップから見える地面の最遠点を求める（上限あり）。
- 将来: 地図で目的地を指定し、道のりに沿って案内する。ゴールの決め方は`GoalProvider`として差し替えられるようにする。

### 2.3 常時表示（画面上部）

- ユーザーの歩行速度
- 予測アルゴリズムの動作状況（FPS、検出数、追跡数、各処理の時間、自己位置推定の状態、入力ソース）

### 2.4 メニュー

- 画面左下のハンバーガーメニューを押すと、画面下からドロワーがスッと表示される。
- ドロワー内に各オプションを格納する。
  - デバッグモード（**デフォルト: オン**）
  - 入力ソース（カメラ / 動画を選ぶ）
  - （その他オプションは実装に応じて追加）

### 2.5 デバッグモード

デバッグ時に「各処理が正常に動いているか」がわかることを優先する。最初は作り込みすぎない。

- 各他歩行者の予測経路を表示する（サンプル軌道の線）。
- 推奨経路を線だけでなく、「衝突しない確率」のグラデーション（地面のヒートマップ）でも表示する。
- キャプチャ映像のコントラストを下げ、全体を白っぽく加工してオーバーレイを見やすくする。
- その他、デバッグに役立つ情報（検出枠、トラックID、距離、候補経路、地面平面、ゴール）を表示する。

### 2.6 予測ホライズン N

- **最接近時刻(CPA)ベースの可変N**を採用する（詳細は [TECH_SELECTION.md](TECH_SELECTION.md) §3.3）。
  - 相対位置p、相対速度vから t_cpa = max(0, −p·v / |v|²) を求め、N = clamp(t_cpa + τ, N_min, N_max) とする。
  - 相対速度がほぼ0のときは N = clamp(d / v_user, N_min, N_max)。
- 当初案の「距離 / ユーザー速度」方式は採用しない（同方向に歩く人に対してNが短すぎ、停止時に発散するため）。

### 2.7 距離・空間の推定

- **画像からの距離推定（単眼メトリック深度）を主軸にする**。ライブ映像でも、事前に撮影した映像でも同じ方法で動かすため。
- LiDARの深度は主軸にしない（精度が足りないため）。

### 2.8 動画入力

- iOSの写真ライブラリ（Macではファイル）から選んだ**普通の動画**を入力し、ライブ時と同じパイプライン・UIを重ねて動作を再現する。
- ARKitなどの付加データは前提にしない（記録モードは作らない）。
- 経路予測モデルの評価に使う。

### 2.9 Mac上でのテスト

- 同じアルゴリズム・UIをMac上で動かし、動画を入力してテストできるようにする。
- アルゴリズムのコアはヘッドレスでも`swift test`できるようにする。

## 3. 非機能要件

- オンデバイス完結（推論・計算すべて端末内）。
- 目標: 描画60fps、検出10Hz以上、深度推定5Hz以上、計画10Hz（iPhone 15 Pro）。
- Gitで管理する（ブランチ: `master`）。
