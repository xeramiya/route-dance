# route-dance 仕様書

> ステータス: ドラフト（技術選定レビュー待ち）
> 最終更新: 2026-10-17

## 1. 概要

歩行者向けのiOS ARアプリ。カメラ映像から周囲の歩行者の行動を予測し、ユーザーが他の歩行者とぶつからずに歩ける確率の高い経路を算出して、映像上に重ねて表示する。

- 処理はすべてデバイス上で完結する（ネットワーク通信なし）。
- UIのイメージは自動運転車の実験映像のように、リアルタイム映像の上にユーザーが歩くべき一本の道筋を重ねるもの。

### 用語

| 用語 | 意味 |
| --- | --- |
| ユーザー | アプリを使う歩行者本人（カメラを持っている人） |
| 他歩行者 | ユーザー以外の歩行者。軌道予測の対象 |
| 推奨経路 | ユーザーがたどるべき経路 |
| 予測経路 | 各他歩行者が今後とりそうな経路 |
| 予測ホライズン N | 他歩行者の経路を何秒先まで予測するか |

## 2. 機能要件

### 2.1 推奨経路の表示（通常モード）

- 推奨経路を一本の線として映像上（地面上）に描画する。
- 推奨経路は**ユーザーの現在の歩行速度でたどれるもの**とする。
- どうしても減速が必要な区間は色で示す。
  - デフォルト（現在速度で通行可能）: 緑
  - 減速が必要: 黄 → 赤（必要な減速量が大きいほど赤）のグラデーション
- 推奨進行方向を示す**コンパス型矢印**を表示する。360°回転し、推奨経路の進むべき向きを指す。

### 2.2 常時表示（画面上部）

- ユーザーの歩行速度
- 予測アルゴリズムの動作状況（例: 追跡人数、推論時間、FPS、トラッキング状態）

### 2.3 メニュー

- 画面左下のハンバーガーメニューを押すと、画面下からドロワーがスッと表示される。
- ドロワー内に各オプションを格納する。
  - デバッグモード（**デフォルト: オン**）
  - （その他オプションは実装に応じて追加）

### 2.4 デバッグモード

デバッグ時に「各処理が正常に動いているか」がわかることを優先する。最初は作り込みすぎない。

- 各他歩行者の予測経路を表示する（線、または確率のグラデーションマップ）。
- 推奨経路を線だけでなく、「衝突しない確率」のグラデーションでも表示する。
- キャプチャ映像のコントラストを下げ、全体を白っぽく加工してオーバーレイを見やすくする。
- その他、デバッグに役立つ情報（検出枠、トラックID、距離など）を表示する。

### 2.5 予測ホライズン N

- 初期定義: **N = ユーザーが他歩行者の現在位置に到達するまでの秒数**（= 距離 / ユーザー速度）。
  - 近くの他歩行者は短いN、遠くの他歩行者は長いNになる。
- 調査の結果、より良い方法があれば採用する（→ [TECH_SELECTION.md](TECH_SELECTION.md)）。
- **提案（レビュー待ち）**: 相対速度を考慮した最接近時刻(CPA)ベースの可変Nをデフォルトにし、d/v方式は設定で切り替えられるよう残す。詳細は TECH_SELECTION.md §3.3。

### 2.6 動画入力による評価機能

- 事前に撮影した動画（iOSの写真ライブラリから選択）を入力し、ライブ時と同じパイプライン・UIを重ねて動作を再現する。
- 経路予測モデルの評価に使う。

### 2.7 Mac上でのテスト（可能なら）

- 同じアルゴリズム・UIをMac上で動かしてアルゴリズムをテストできるようにする。
- 同一のアルゴリズム・UIで実現が難しい、または時間がかかりすぎる場合は対象外とする。

## 3. 非機能要件

- オンデバイス完結（推論・計算すべて端末内）。
- リアルタイム性（目標値は技術選定で決める）。
- Gitで管理する。
